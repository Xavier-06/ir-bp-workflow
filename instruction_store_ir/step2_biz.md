## 职责
- 拆解公司收入模型（收入构成、定价逻辑、客户结构）
- **UE 经济模型标准化**：单用户/单店/单GMV的完整收入-成本拆解
- 分析单位经济学（CAC/LTV/毛利率/边际成本/复购率）
- 评估护城河强度（品牌/网络效应/转换成本/规模/IP/数据）
- **供应链分析**：供应商集中度、议价力、产能利用率、切换成本
- **渠道效率分析**：各渠道收入占比+成本结构对比、同店增长
- **用户与市场分析**：用户画像、分层、渗透率、天花板
- **利润池矩阵**：哪条业务线是利润引擎
- **经济利润分析**：ROIC - WACC 差值
- 分析 GTM 策略和增长飞轮

## 核心判断：这公司怎么赚钱？护城河有多深？

> 商业模式分析的根本问题不是"有哪些收入"，而是"每一块钱收入的获取成本和可持续性"。

### 必须回答的6个问题（输出前自检）
1. 每条业务线的收入是怎么来的？（谁付钱、付多少、为什么付）
2. 每获取一个客户/卖出一件产品，公司赚多少？（单位经济学）
3. 公司的供应商和渠道是否在榨干利润？（供应链+渠道）
4. 用户为什么离不开？（护城河量化）
5. 哪条业务线在真正驱动利润增长？（利润池矩阵）
6. 护城河在变宽还是变窄？（侵蚀信号）

## 输出格式

Markdown 文件，必须包含以下章节（按顺序）：

### 1. 收入模型
- 各业务线收入占比、YoY 增速、定价逻辑
- ⭐ **收入质量分析**：
  - 经常性 vs 一次性收入比例
  - 高毛利业务 vs 低毛利业务的收入趋势
  - 单一客户/渠道集中度（前 3 大客户收入占比）
- ⭐ **业务线交叉验证**：各业务线之间是否存在协同或相互吞噬

### ⚠️ 强制拆解规则（F级）
- **单业务线/子项占集团总收入>10%**: 必须拆解至子业务名称+收入+同比增速+利润率
- **"其他"合计占比>15%**: 禁止保留为"其他"，必须拆解至最大单项目占比<10%
- **示例**: 若"其他业务"占比24.85%，必须列出菜鸟/饿了么/大文娱/高德等子业务的各自收入/增速/利润率

### 2. ⭐ 单位经济学（UE 模型 — 强制模板）

根据公司业态选择对应模板（必选其一）：

#### 模板 A：消费/零售/连锁
```
单店UE模型（年度）：
  单店营收 = 客单价 × 日均客流 × 营业天数
  单店毛利 = 单店营收 × 毛利率
  单店运营成本 = 租金 + 人工 + 水电 + 营销分摊
  单店净利润 = 单店毛利 - 单店运营成本
  单店回收期 = 单店初始投入 / 单店年净利润
  同店增长率（SSSG）= (本期同店营收 - 上期同店营收) / 上期同店营收
```

#### 模板 B：互联网/平台
```
用户UE模型（年度）：
  ARPU（每用户平均收入）
  ⚠️ ARPU必须按用户分层展示（如VIP会员 vs 普通用户），标注分层依据。禁止仅给出全局均值。
  CAC（获客成本）= 营销费用 / 新增用户数
  ⚠️ CAC必须多源交叉验证（不得仅依赖管理层披露）。与行业均值（电商150-200元、SaaS 200-500元等）对比标注偏差。偏差>50%须解释原因。
  LTV = ARPU × 毛利率 × 平均用户寿命
  LTV/CAC 比值（≥ 3 为健康）
  用户留存率曲线（D1/D7/D30/年度）
  付费率 = 付费用户 / MAU
```

#### 模板 C：科技/硬件/SaaS
```
产品UE模型（年度）：
  单产品ASP（均价）
  单产品COGS（成本）
  单产品毛利 = ASP - COGS
  客户获取成本（如适用）
  客户生命周期价值（如适用）
  NDR（净收入留存率，SaaS适用）
```

**数据缺失处理**：
- 能算出 CAC/LTV → 必须算，附计算公式和假设
- 数据不足以支撑 → 标注"公司未披露用户/单店数据，缺少[A/B/C]"
- 部分数据可估算 → 标注"估算"和假设条件

### 3. 成本结构与利润池
- 固定 vs 可变成本、规模效应趋势
- ⭐ **利润池矩阵**（强制表格）：

| 业务线 | 营收占比 | 毛利占比 | 利润贡献度判断 | 趋势(↑→↓) |
|--------|---------|---------|-------------|----------|
| 业务-A | XX% | XX% | 利润引擎/现金牛/亏损拖累 | ↑/→/↓ |
| 业务-B | XX% | XX% | ... | ... |

- 明确标注：哪条线在"养"哪条线

### 4. ⭐ 供应链分析（全新）
- 核心供应商/原材料依赖度（前3大供应商采购占比）
- 供应链议价力评估（强/中/弱，附论据）
- 产能利用率（如有）+ 产能扩张计划
- 供应商切换成本（高/中/低）
- 供应链地域集中度风险

### 5. ⭐ 渠道效率分析（全新）
- 各渠道收入占比 + 对应成本结构
- 渠道扩张速度 vs 同店增长质量对比
- 线上 vs 线下的利润贡献度
- 渠道冲突风险评估（如直营 vs 经销商）

### 6. ⭐ 用户与市场分析（全新）
- 用户画像（年龄/地域/消费力分层，如有数据）
- 用户增长趋势 + 各获客渠道效率
- 复购率/留存率趋势（如有）
- 目标市场渗透率 + 天花板估算（引用 step2 行业数据）
- ⭐ **IP/品牌矩阵分析**（⭐全新 — 消费/IP类公司必做）：
  - 核心IP收入集中度（Top 3 IP占总收入%）
  - IP生命周期阶段（上升/成熟/衰退）
  - 新IP孵化节奏和成功率
  - 自有IP vs 授权IP占比

### 7. ⭐ 平台经济学（互联网/平台类公司必做）
- GMV/交易额 + 抽佣率
- 双边网络密度（供给端 × 需求端匹配效率）
- 广告加载率（ad load）+ eCPM 趋势
- 补贴效率：每元补贴带来的GMV增量

### 8. 护城河评分
- 1-5 分，按维度拆分（含评分定义）
- ⭐ 每个维度附量化的竞争对标（不只是定性）
- ⭐ **护城河侵蚀信号监测**：
  - 竞品是否在缩小差距？（产品参数/价格/市场份额）
  - 用户切换成本是否在降低？
  - 监管是否在削弱壁垒？
- **必须与至少 2 家核心竞品做护城河评分对比**
- ⚠️ **独立数据验证**: 护城河评分引用的量化指标（专利数、市场份额、研发投入等）必须优先引用第三方独立来源，不得仅依赖公司自述。

评分体系（1-5 分）定义：
- **1 分 = 无护城河**：任何新进入者都能复制
- **2 分 = 弱护城河**：有一定壁垒但易被突破
- **3 分 = 中等护城河**：需要显著投入才能复制
- **4 分 = 强护城河**：难以复制，需要数年积累
- **5 分 = 极强护城河**：几乎不可复制（如网络效应、独占资源）

**评分硬规则**：
- **"未知"/"未披露"的维度给 2 分**（假设弱），不能标"未知"然后不计入
- **每个维度必须附至少一条事实论据**，不能只给分数
- **与竞争对手对比时，对方的分数也需要事实支撑**

### 9. 增长飞轮与风险
- 正反馈循环机制图（文字描述各环节的因果关系）
- ⭐ **飞轮断裂条件**：什么情况会导致飞轮停转或逆转
- 商业模式风险：依赖度、可替代性、监管风险

## 数据纪律（硬规则）

### 收入拆分必须有来源
- **各业务线收入占比必须引用年报/季报的分部信息**
- 不能凭印象写"约占 30%"——要么有来源写精确值，要么写"公司未单独披露"
- **海外收入占比是高频出错点**——必须引用年报中的地区分部数据

### 门店/渠道数量
- 必须标注"截至 YYYY-MM-DD"和来源
- 线上/线下/海外门店分别计数
- 数据必须与 enriched_data_pack.json 一致（step1_industry 与本 step 同波并行，无法互查）

### UE模型数据
- CAC/LTV 必须是实际计算或标注"公司未披露"
- LTV/CAC 比值必须有明确计算过程
- UE数据至少标注计算所用的核心假设

### 禁止编造
- 没搜到的 CAC/LTV 数据，写"公司未披露"
- 护城河评分的每个维度必须有至少一条事实论据
- 不能因为某竞品知名度高就给满分

## 自主补搜规则（硬规则）

**核心原则：发现数据缺口时自主补搜，不要写"待核实"就完事。**
补搜的通用纪律（工具路由优先级、闭环流程、3 轮上限、来源标注）以 brief 中「补搜工具使用指南」和派发 prompt 中「数据源路由」表为准，本 step 不重复。

### 本 step 补搜触发条件
1. **关键数据缺失** — 收入结构、渠道占比、IP授权数据等核心指标搜不到
2. **来源不足** — 关键论断只有 0-1 个来源
