### ⚠️ 脚注来源回溯（子代理 MD 无脚注时的 fallback — 2026-06-28 新增）

**问题**：部分子代理可能只在 facts JSON 中写 source_url，而未在 MD 正文中写 [^N] 脚注。统稿时必须处理这种情况。

**执行步骤**：
1. 读取每个子代理的 MD 报告后，检查是否有 `[^N]` 脚注标记
2. **如果 MD 中无脚注**，必须读取对应的 `-facts.json` 文件（路径：`outputs/bp_phase2_{slug}-facts.json`）
3. 从 facts JSON 中提取每条 fact 的 `source_url` 字段
4. 将 fact 内容与 MD 正文中的关键数据点匹配，用 source_url 作为脚注来源
5. 如果 facts JSON 的 source_url 为空或非 URL，标注为：
   - `天眼查结构化数据（天眼查 MCP）` — 来源为 TYC 工具
   - `BP自述 — 无外部来源URL` — 来源为 BP 原文
   - `内部数据源` — 其他无 URL 来源

**示例**：
- 子代理 MD 写"营收约1.78亿元"，无脚注 → 读 facts JSON 找到对应 fact → source_url 为空 → 脚注：`[^N]: BP自述 — 无外部来源URL`
- 子代理 MD 写"奇瑞车规级芯片联合实验室已投产"，无脚注 → 读 facts JSON 找到对应 fact → source_url 为 `http://ah.people.com.cn/...` → 脚注：`[^N]: 人民网 — http://ah.people.com.cn/... (日期)`

**禁止行为**：
- ❌ 发现子代理无脚注就直接跳过不补
- ❌ 只从 search_deep(Bash) 重新搜索来源（浪费时间且可能引入不一致）
- ✅ 优先从 facts JSON 回溯，只有 facts JSON 也无 URL 时才用 search_deep(Bash) 补充

### ⛔ 脚注来源格式（铁律 — 违反则报告不合格）
每条脚注定义**必须**包含真实外部 URL，格式：
  [^N]: 来源名称 — https://具体URL (访问日期)

**禁止行为（任何一条命中 = 脚注无效）：**
  ❌ 只写内部文件名：[^N]: bp_phase2_xxx.md
  ❌ 只写内部 JSON：[^N]: bp_fact_store.json(F001)
  ❌ 不写 URL 只写来源名：[^N]: 天眼查工商信息
  ❌ 省略 URL：[^N]: 行业报告 — 2024年半导体激光市场

**正确示例：**
  ✅ [^1]: 天眼查 — https://www.tianyancha.com/company/12345 (2026-06-10)
  ✅ [^2]: Yole Intelligence — https://www.yole.com/reports/laser-market-2025 (2025-12)
  ✅ [^3]: 长光华芯年报 — https://www.sse.com.cn/disclosure/listedinfo/announcement/xxx.pdf (2026-03-28)
  ✅ [^4]: 36氪 — https://36kr.com/p/1234567890 (2026-05-15)

如果子代理的脚注只有内部文件名，统稿时必须根据上下文**回溯到原始搜索来源**，找到外部 URL 后重写脚注。
如果某个数据点确实没有外部 URL（如 BP 自述数据），脚注标注为：[^N]: BP自述 — 无外部来源URL

## 技术壁垒量化评估（必须独立成节）

## ⚠️ 统稿防缺陷规则（最高优先级）

### 规则1：产品矩阵必须独立成章
不能把产品信息散落在技术章节中。产品矩阵是报告第二章，在技术分析之前。

### 规则2：数值自洽性检查（统稿必须执行）
统稿完成前，**必须**逐项检查以下数值一致性，如发现矛盾必须在报告中标注并修正：

1. **市占率 vs 总营收**：如果执行摘要中引用了市占率，检查该市占率是否用细分品类收入（而非公司总营收）计算。如果公司有多产品线，市占率必须用对应品类的收入。
2. **进口依赖率 vs 国产市占率**：如果报告说"90%依赖进口"同时说某国产厂商"市占率4%"，检查逻辑——90%进口意味着国产总共≤10%，加上其他国产厂商是否超过10%？如果矛盾，修正其中一个。
3. **"唯一/首家"声明**：如果任何维度报告中出现"国内唯一""全球首家"等绝对性声明，统稿时必须独立搜索验证。已建成的同类平台/设施=该声明不成立，应改为"国内少数"或"国内领先"。
4. **渗透率假设**：如果市场推算中使用了渗透率数字，检查是否给出了依据。没有依据的渗透率必须标注为"假设值，待验证"。
5. **市场规模自洽性**：自上而下的第三方数据与自下而上的分场景推算如果偏差>15%，必须在报告中解释差异原因。
6. **财务数据使用一致性**：不能在同一报告中既质疑某财务数据真实性又用其做估值计算。如果质疑，估值中必须标注"基于BP披露数据，未经第三方审计"。
7. **员工数统计口径一致性**：对比本公司与竞品时，必须使用相同口径（全集团vs全集团）。
8. **技术参数引用一致性**：系统级指标和器件/组件级指标必须区分，不能在前面写"系统级"后面用同一数字暗指器件级。
9. **BP声称不可编造**：验证表中的每条"BP声称"必须是BP原文确实出现的内容。

### 规则3：预测数据必须附假设条件
所有预测数据（市场规模、增速、渗透率）必须附上：
- 完整的自下而上推算逻辑
- 关键假设条件列表
- 假设条件变化对结论的敏感性分析（如增速降低5%，结论如何变化）

### 规则4：技术路线不可强行组合
如果子代理输出了"A技术+B技术双重路线"等组合结论，统稿时必须回溯BP原文验证：
- BP是否明确将两者关联？
- 如果BP只是分别提到两个技术点，统稿时必须拆开呈现，不能写成"双重路线"
- 子代理的推断结论在统稿时可以保留，但必须标注为"分析推断，非BP原文声称"

### 规则5：可比公司必须主营业务重合 ≥60%
估值部分的可比公司必须与公司核心业务属性匹配：
- 必须选同细分领域/同技术路线的垂直可比公司，不能用跨领域的通用公司
- **每家可比公司必须说明主营业务重合度**（标的公司主营什么、可比主营什么、重合度百分比和判断依据）
- 主营业务重合度 <60% 的必须剔除并说明原因
- 如果公司有多业务线，分线呈现可比公司

### 规则5.5：估值章节只呈现事实（统稿硬规则）
统稿时估值章节（§十一）只能包含以下内容：
1. **融资历史与各轮估值变化时间线表**（必须覆盖每一轮融资）
2. **可比公司估值对标**（仅呈现 PE/PS/市值等事实数据，每家含主营业务重合度说明）
3. **可比公司筛选依据**（主营业务重合度逐一说明）
4. 可比交易参考

**禁止出现**：
- ❌ 投资回报模型（MOIC/IRR 矩阵）
- ❌ 估值区间推荐或"合理估值"判断
- ❌ 投资建议
- ❌ 估值折价分析（流动性折价/风险折价等建议性内容）

### 规则6：风险缓释因素必须体现
不能只写风险不写缓释。每条重大风险必须同时呈现：
- 风险本身的严重性
- 现有的缓释措施（如有）
- 缓释措施的可靠性评估
